## 0. Cách dùng file này

1. **Bootstrap session mới:** `AGENTS.md` → file này (đọc từ đầu) → làm việc → cập
   nhật mục 2 và mục 6 **cuối mỗi session**. Đừng tin trí nhớ.
2. **Trạng thái item:** `⬜` chưa làm · `🔄` đang làm (kèm ngày + người) · `✅` xong
   (kèm ngày + bằng chứng) · `⛔` blocked (kèm lý do) · `📌` quyết định đã chốt.
3. **Không xoá dòng đã xong** — đánh dấu ✅ giữ nguyên để truy vết, đúng quy ước bia
   mộ của repo.
4. **"Xong" phải có bằng chứng thật**: lệnh đã chạy, kết quả, link file. Không ghi
   "xong" không bằng chứng.
5. **Mâu thuẫn docs vs file này:** về *tiến độ điều hành*, file này thắng; về *spec
   sản phẩm*, docs thắng. Thấy mâu thuẫn → ghi vào mục 4, đừng im lặng sửa.
6. **Nhật ký (mục 6) là append-only** — không sửa dòng cũ.
7. **Làm parallel:** mỗi task đúng một người giữ. Trước khi nhận task, xem cột "Phụ
   thuộc" và trạng thái của nó.

### Hợp đồng test (TDD Route)

- **Mode:** off. **Decision:** skipped — repo không có yêu cầu TDD strict, và
  AGENTS.md mục 4 đã chốt *"acceptance criteria là test case"*: mỗi FR chỉ xong khi
  **toàn bộ** criteria Given/When/Then của nó pass.
- **Test posture:** post-change regression + evidence thật (kết quả script Phase 0,
  thao tác thử của owner).
- **Verification:** mỗi task ở mục 3 ghi rõ bằng chứng phải có trước khi đánh ✅.

  là lựa chọn đúng, nhưng **DB phải mở trong Web Worker**: VFS `opfs` cần
  `Atomics.wait()` (lib từ chối main thread, và từ chối *trong im lặng* — không log,
  không request proxy worker), VFS `opfs-sahpool` cần `createSyncAccessHandle` (Chrome
  chỉ expose trong Worker). Đã đo thật trên Chrome 152 bằng `npm run e2e:opfs`, đừng
  suy đoán lại. Hệ quả vận hành: host production PHẢI gửi COOP/COEP (SharedArrayBuffer);
  không gửi được thì app tự rơi sang `opfs-sahpool` (vẫn persist) rồi mới tới `:memory:`
  kèm cảnh báo. Guard chống tái diễn: hàng **"Sống qua F5"** ở `?screen=storage-check`
  và `npm run e2e:storage`. Vẫn giữ nguyên phần còn lại: đừng đổi sang IndexedDB rồi migrate.
